# 多邻国/抖音式学习模式评估与操作报告

日期：2026-05-25
仓库：`D:\Codex-GitHub\00-SightReading_3.0`
来源文档：`新增一个多邻国_抖音式的学习模式！.docx`

## 1. 结论

这个方向是合理的，而且和当前项目的底层结构比较匹配。建议把它定义为一次“学生端学习路径重构”，核心目标是：

- 首页从“知识点四宫格”改成两个入口：主线闯关、自由练习。
- 主线闯关变成教师编排的线性成长路线，可以混合单音、双音/音程、符号、音型。
- 自由练习保留学生自选能力，用于查漏补缺和短时随机训练。

但不建议直接改代码。因为这是导航结构、关卡模型、进度解锁和统计语义的共同变化，应该先走 OpenSpec 提案，再分阶段实现。

## 2. 当前代码现状

已具备的基础：

- 学生端路由在 `src/App.tsx`，目前 `/client` 首页进入四个模块，`/client/module/:moduleId` 进入关卡选择。
- 当前首页组件是 `src/pages/client/MainMenu.tsx`，四个模块直接平铺。
- 当前关卡选择组件是 `src/pages/client/StageSelector.tsx`，已经有“闯关模式 / 练习模式”的雏形。
- 自由练习已有两块基础：
  - 单音练习：`/client/practice/notes`
  - 音程练习：`/client/practice/intervals`
- 关卡数据来自 `customStages`，`getAllStages(moduleId)` 当前按模块取关卡。
- 进度数据已有 `studentProgress` 和 `unlockNextStage`。

需要注意的问题：

- `StageSelector.tsx` 里当前解锁逻辑被临时写成 `const isUnlocked = true`，旁边有 TODO 提醒恢复基于 `studentProgress` 的锁定。
- 当前 `studentProgress` 是按模块存储的，例如 `notes/theory/patterns/symbols`。如果主线关卡要混合题型，需要新增独立的主线进度，而不是复用某个模块的进度。
- `InteractiveQuiz.tsx` 目前通过 `stage.module` 解锁下一关。混合关卡如果仍伪装成某个 module，会让进度、统计和返回路径变得含糊。
- 自由练习还没有覆盖符号、音型，也没有真正的“三分钟一组”会话结束页。

## 3. 对产品设想的判断

### 主线闯关

建议定位为教学核心。教师负责安排顺序，学生不需要理解“我今天该练哪个知识点”。这很适合视奏训练，因为初学者通常不知道如何安排单音、双音、音型之间的比例。

主线关卡不应该只是把现有模块列表换个皮肤，而应该拥有一个独立的路线模型：

- 路线关卡可以混合多个 module 的题。
- 每一关可以有标题、说明、题数、所属阶段、排序。
- 解锁进度独立保存，例如 `adventureUnlockedLevel`。
- 完成后再解锁下一关。

### 自由练习

建议保留，但从首页降级为辅助入口。它解决的是“我知道自己想练什么”的场景：

- 单音：按音域、升降号、输入方式练习。
- 双音/音程：按类型、方向、谱号、旋律/和声音程练习。
- 符号、音型：后续可以增加题库随机练习。
- 三分钟一组可以作为自由练习的 MVP 后续项，不必和首页重构绑在同一批。

### 抖音式

当前 docx 正文主要描述的是多邻国式线性路线。文件名里的“抖音式”可以理解为另一个体验方向：快速、沉浸、连续刷题。

建议先不要把“路线图”和“上下滑刷题”混成一个大版本。更稳的做法：

- MVP 先做多邻国式主线入口和线性解锁。
- 后续再评估是否给自由练习增加“沉浸式刷题流”，比如单题全屏、连续下一题、短时反馈、上下滑切换。

## 4. 建议实施路线

### 阶段 0：提案确认

先创建 OpenSpec change，例如：

```text
openspec/changes/add-adventure-learning-mode/
```

建议包含：

- `proposal.md`：说明为什么从知识点入口改成学习路径入口。
- `design.md`：说明主线关卡模型、路由、进度、兼容旧数据的策略。
- `tasks.md`：拆成可验收任务。
- `specs/client-learning-path/spec.md`：学生端入口、主线、自由练习、解锁的要求。

确认后再写功能代码。

### 阶段 1：首页入口重构

改造 `/client`：

- 第一入口：主线闯关。
- 第二入口：自由练习。
- 保留账号菜单和反馈入口。
- 不再把四个知识点模块直接放在第一屏。

新增建议路由：

```text
/client/adventure
/client/adventure/quiz/:stageId
/client/free
/client/free/:moduleId
/client/practice/notes
/client/practice/intervals
```

### 阶段 2：主线闯关 MVP

先不要急着做 30 关完整系统。建议先验证 3 到 5 关：

- Lv.1 单音坐标音
- Lv.2 单音附近上行/下行
- Lv.3 双音/音程入门
- Lv.4 单音复习
- Lv.5 双音级进/跳进

技术上先用现有 `customStages` 作为素材池，但在学生端创建一个独立的 `AdventureMap` 页面，把这些关卡按教师配置顺序串起来。

如果要真正支持混合关卡，有两种实现：

- 方案 A：扩展 `CustomStage.module`，允许 `module = 'adventure'`，但 stage 内的每道 slice 保持自己的 module。
- 方案 B：新增 `learningPathStages` 数据模型，专门服务主线。

推荐方案 B 更干净，但工程量略高。MVP 可先用方案 A 的思想做前端适配，但要在 OpenSpec 里说清楚迁移方向。

### 阶段 3：恢复并独立化解锁

必须把当前全解锁测试逻辑恢复。主线进度建议独立于模块：

```typescript
studentProgress: {
  notes: number;
  symbols: number;
  theory: number;
  patterns: number;
  adventure?: number;
}
```

如果后续要同步到 Supabase，需要确认 `student_progress.module` 是否允许 `adventure` 这个值。

### 阶段 4：自由练习中心

把现在四模块入口迁移到 `/client/free`，但文案和交互改成“我要自己练”：

- 单音：进入现有单音参数页。
- 双音/音程：进入现有音程参数页。
- 符号：先进入题库随机练习，后续再加分类。
- 音型：先进入题库随机练习，后续再加范围或类型筛选。

### 阶段 5：三分钟一组与排行榜

这部分不要放进第一批，原因是它牵涉到 session 记录、结束页、排行榜口径。建议等主线入口稳定后再做：

- 练习 session 开始/结束时间。
- 三分钟结束页：总题数、正确率、常错题。
- 排行榜只展示完成后的正向结果，不在做题中制造压力。

## 5. 主要风险

- 数据模型风险：混合关卡不能继续简单按 `stage.module` 解锁，否则主线进度会和模块进度混在一起。
- 兼容风险：现有教师端 `CustomStageEditor` 是按模块创建关卡的，主线编排如果也放到这里，需要 UI 上区分“模块关卡”和“主线关卡”。
- 范围膨胀风险：如果同时做首页、路线图、混合题、三分钟、排行榜、抖音式刷题，容易失控。建议先做主线 MVP。
- 当前工作区风险：仓库已有未提交改动，`AGENTS.md` 已修改，`CODEX_ADMIN.md` 未跟踪。后续开发前应先确认这些文档改动是否纳入本地变更。

## 6. 验收标准建议

MVP 完成时应满足：

- `/client` 首页只显示“主线闯关”和“自由练习”两个主要入口。
- 点击主线进入线性路线图，至少能显示 3 到 5 个关卡。
- 未解锁关卡不可进入，完成当前关卡后下一关解锁。
- 主线关卡可以至少串联单音和双音/音程两种题型。
- 自由练习仍能进入现有单音和音程练习，不丢失现有能力。
- `npm run build` 通过。
- 用本地浏览器验证桌面和手机宽度下没有文字重叠、按钮溢出、空白谱面。

## 7. 我的推荐操作方式

推荐你确认下面这个范围：

1. 先做 OpenSpec 提案，不直接写功能。
2. MVP 只做“首页双入口 + 主线路线图 + 独立解锁 + 自由练习中心迁移”。
3. 混合关卡先支持单音和双音/音程，符号和音型进入第二批。
4. 三分钟一组、排行榜、抖音式沉浸刷题流放到后续提案。
5. 全程只在本地仓库操作；未经你同意不 push、不 deploy。
