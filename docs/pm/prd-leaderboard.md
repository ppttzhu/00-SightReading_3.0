# PRD：排行榜系统

## 1. 背景与目标

当前答题结果（分数、正确率、用时）完全是 React 组件临时状态，页面刷新即丢失。系统缺乏让用户感知成长的机制。

**核心目标：**

- 让用户有成就感，驱动持续使用
- 对答题情况做多维度记录与排名
- 教师端可查看学生整体数据

### 1.1 无压力练习原则（核心设计约束）

**做题过程中**：不展示计时器、不展示实时排名、不做速度催促、不做红色/黄色警告。用户只需沉浸在做题本身。

**完成之后**：所有数据（用时、积分、正确率）以正向方式呈现。积分规则和排名公式均为后端隐式计算，用户做题时无感知。

- 积分是"你获得了多少"，不是"你失去了多少"
- 排名是"你的成长记录"，不是"你比别人差在哪里"
- 进步是自己跟自己比，横向对比只做展示不做强调

## 2. 积分体系

### 2.1 基础规则

| 行为 | 积分 | 备注 |
|------|------|------|
| 正确作答 | +10 | 基础分 |
| 连续正确 Combo | +10 × combo 系数 | combo ≥ 3 时生效，系数 1→1.2→1.5→2.0，有上限 |
| 关卡通关 | +50 | 完成一个 stage |
| 挑战模式三星 ⭐⭐⭐ | +150 | 全部答对 |
| 挑战模式二星 ⭐⭐ | +100 | 错 1-2 题 |
| 挑战模式一星 ⭐ | +50 | 错 3-5 题 |
| 挑战模式未通关 | 0 | 错超 5 题或无成绩 |

### 2.2 防刷机制

- 连续 < 1 秒的极速点击 → 本题作废，不扣分也不计分
- 挑战模式重刷只记最佳成绩（星级覆盖），积分不累加

### 2.3 模块权重

四个模块（notes / symbols / theory / patterns）**不设权重差异**。积分直接累加，模块各自独立排名。

---

## 3. 正确率计算

**方案 B：分母 = 全部出现过的题目**

```
正确率 = 答对题数 / (答对题数 + 答错题数)
```

防刷仅拦截 < 1 秒的极速连点（明显乱点），其余正常作答全部计入。规则简单透明，用户一眼看懂。

上榜门槛：该模块至少完成 **20 道题**。

---

## 4. Skip 机制

### 规则

- 每关有 **3 次** skip 机会（仅 InteractiveQuiz 关卡模式）
- 跳过的题**直接丢弃**，不再回来
- **不计入任何统计**（不计分、不扣分、不入正确率分母）
- **不入错题本**（为后续错题本功能预留边界）
- combo 不中断也不增长

### 边界

```
正确 → 答对记录 → 计入正确率分子
错误 → 错题记录 → 计入正确率分母，进错题本
跳过 → 不留记录 → 不计入任何统计
```

### PracticeQuiz / IntervalPractice

自由练习模式无限制，点击"换一题"即可跳过当前题，行为同上。

---

## 5. 挑战模式

定位：学完常规内容后来"证明自己"的关卡，由教师创建。

- 答题结果按星级记录（3 星 / 2 星 / 1 星 / 无）
- 允许重刷，只保留最佳成绩
- 积分按最佳成绩发放一次（不累加）
- 排行榜上显示 ⭐ 标识

---

## 6. 排行榜维度

### Phase 1 — MVP

| 维度 | 说明 | 聚合粒度 |
|------|------|----------|
| 总积分榜 | 所有模块积分之和 | 用户 |
| 单模块积分榜 | notes / symbols / theory / patterns 各自 | 用户 × 模块 |
| 正确率榜 | 正确率排名（≥20 题门槛） | 用户 × 模块 |
| 综合正确率榜 | 四模块正确率均值 | 用户 |

### Phase 2

| 维度 | 说明 |
|------|------|
| 进步排名 | 日环比排名（今日得分 - 昨日得分），鼓励普通用户上榜 |
| 班级排行 | 班级之间对比（总积分、平均正确率、活跃度） |
| 挑战模式榜 | 按星星数 + 积分排序 |

### Phase 3

| 维度 | 说明 |
|------|------|
| 每周之星 | 系统自动选出本周进步最大的用户 |

## 7. 称号系统

称号显示在排行榜用户名旁，作为身份标识和额外激励。

| 称号 | 获取条件 |
|------|----------|
| 🎵 初学者 | 累计答对 50 题 |
| 🎹 练习生 | 累计答对 200 题 |
| 🎼 演奏家 | 累计答对 1000 题 |
| 🏆 挑战者 | 完成 3 个挑战关卡 |
| 🔥 连胜王 | 连续 7 天有练习记录 |
| ⚡ 闪电手 | 平均答题速度 < 2 秒（正确率 > 80%） |
| 📚 学霸 | 正确率 > 95%（答题 > 500 题） |
| 🌟 全才 | 四个模块正确率均 > 80% |

---

## 8. 班级 (team_num)

- 数据库字段：`team_num`（字符串）
- 前端显示：班级
- profiles 表新增该字段
- 教师端可创建/编辑班级、将学生分配至班级
- 排行榜按班级聚合统计数据

---

## 9. 教师端需求

1. **学生总览**：查看每个学生的积分、正确率、最近练习时间
2. **排行榜**：与学生端同一套数据，教师可查看所有人
3. **挑战关卡结果**：查看每道挑战题的完成情况
4. **班级管理**：创建/编辑班级，分配学生
5. **异常检测**：标记可能存在刷分行为的学生（连续满分、答题间隔异常短）

---

## 10. 分阶段路线图

### Phase 1 — MVP

- 积分系统（基础分 + combo + 通关奖励）
- 正确率计算 + 上榜门槛
- 总积分榜 + 模块积分榜 + 正确率榜
- Skip 机制
- 教师端查看排行榜
- 数据存储：Supabase Postgres 新建表

### Phase 2

- 挑战模式星级评分
- 进步排名（日/周环比）
- 称号系统
- 班级体系（team_num） + 班级排行榜
- 防刷监控（教师端异常标记）

### Phase 3

- 每周之星
- 点赞 / 社交互动
- 错题本（复用答题记录）

---

## 11. 数据结构概览（Phase 1）

下划线表示需要新建的表。实际 schema 设计在技术方案阶段细化。

- **_quiz_attempts**（答题记录）：user_id, module, slice_id, is_correct, response_time_ms, combo_at_time, stage_id, created_at
- **_user_scores**（用户积分快照）：user_id, module, total_score, total_correct, total_attempts, updated_at
- profiles 扩展：新增 team_num 字段
- **_badges**（称号，Phase 2）：user_id, badge_type, earned_at
- **_challenge_stars**（挑战模式星级，Phase 2）：user_id, stage_id, stars, best_score, completed_at
